## Why It Changed

The accepted intent ruled deletion out on the reasoning that this work was about
coherence, not removal. Three things learned **after** acceptance changed the
arithmetic, and all three are recorded evidence rather than opinion:

1. **The design gate failed the plan, and `codex-challenge` was the cause of
   nearly every substantive finding** (`audit.md`, 2026-09-03). Its loop has six
   exit conditions where the spec described two; conditions 3 and 4 score in
   `N/5` form, which the planned guard pattern would not have caught; and its
   "eight dimensions" are a different set from the auditor's eight — the schema's
   eighth is `omissions`, the auditor's is `Team & Resources`.

2. **The true scope is 3.7× the accepted estimate.** The intent recorded 10 files
   / 31 lines. A pattern validated against 7 known-positives and 4
   known-negatives before use gives **21 files / 114 lines** in scope.
   `codex-challenge` accounts for **46 of those 114**.

3. **It is the only component with an external dependency.** It cannot run
   without the OpenAI Codex CLI on `PATH`, so the repair carried a permanent
   caveat: the fixtures could be made green while the real loop stayed unproven
   until someone with the CLI ran it.

Deleting it satisfies FR-1 (one verdict currency) more completely than rewriting
it would, because a deleted tool cannot disagree with the gate. It removes the
whole of the plan's only HIGH-risk phase, the only contract change, the only
schema rewrite, and the only external dependency.

**What is genuinely lost**, recorded so the decision is not read as free:
adversarial second-opinion review by a *different model family*. That is a real
capability and nothing replaces it. The design gate's canary and evidence
validator check whether an audit was **done honestly**; they do not provide a
second independent opinion on whether a plan is **good**. Anyone wanting that
now runs the Codex CLI by hand.

Note the irony, recorded rather than hidden: this very plan was improved by a
Codex review (`research/codex-design-review.md`), which found a correctness hole
in the first draft. The tool being deleted is a packaged version of a workflow
that just proved useful. What is being deleted is the *packaging* — the scored
convergence loop, the parser, the fixtures — not the practice.
